| Version | Date | Author | Change |

## 1. Introduction

### 1.1 Purpose
This document specifies the requirements of **Bookmate**, a smart library Android app with AI integration. It describes what the system must do and the qualities it must have. It is the basis for the Design, Implementation, and Testing phases.

### 1.2 Scope
Bookmate lets library users search and borrow books, get AI book recommendations, and get AI summaries of books. It lets library staff (Admin) manage the book catalog and loans.

**In scope:** member accounts, book search and details, borrowing, reservation, renewal, ISBN scan, AI recommendation, AI book summary and chat, and Admin functions for catalog and loans.

**Out of scope:** payments and fines, iOS or web version, offline mode, social features (reviews, sharing), integration with an existing university library system, and librarian upload of full book files.

### 1.3 Definitions
| Term | Meaning |
|---|---|
| Member | A normal library user |
| Admin | Librarian or library staff who manages books and loans |
| Loan | A record that a member has borrowed a book, with a due date |
| Reservation | A request to borrow a book that is currently unavailable |
| ISBN | International Standard Book Number printed on a book |
| Public-domain book | A book whose copyright has expired; its full text can be used freely |
| AI summary | A summary of a book, chapter, or page range generated by an AI model |
| FR / NFR / UC | Functional Requirement / Non-Functional Requirement / Use Case |
| SR | Business requirement number in the System Request |

## 2. Overall Description

### 2.1 Product Perspective
Bookmate is a new standalone Android app. It uses external services: book data (Google Books API, Open Library API), public-domain book text (Project Gutenberg), an AI model (Gemini API), and on-device barcode scanning (ML Kit). Account and library data storage will be decided in the Design phase.

### 2.2 User Classes
| User | Description | Main needs |
|---|---|---|
| Member | Student or library user, comfortable with mobile apps | Find, borrow, and understand books quickly |
| Admin | Librarian or library staff | Keep the catalog correct and record returns |

### 2.3 Operating Environment
Android smartphone, with internet connection for book data and AI features. Minimum Android version is decided in the Design phase.

### 2.4 Constraints
- Kotlin and Android Studio.
- Full-text AI summaries only for public-domain books (copyright).
- AI answers must show an accuracy notice.
- API keys must not be stored in the public repository.
- Free tools and free-tier services only.
- Delivery around mid-December 2026 by a three-member team.

### 2.5 Assumptions and Dependencies
| ID | Assumption |
|---|---|
| A-01 | Default loan period is 14 days and a loan can be renewed once. Both values are configurable and must be confirmed by the team. |
| A-02 | The UI language is English. |
| A-03 | The demo catalog is a small set of books, with 5-10 public-domain books that have full text. |
| A-04 | External services (AI and book APIs) are available and their free tiers are enough for the demo. |
| A-05 | The Admin account is created by the team (no public Admin sign-up). |

### 3.2 Non-Functional Requirements

Numbers marked as **target** are goals to be verified in testing.

| ID | Category | Requirement |
|---|---|---|
| NFR-01 | Usability | A new Member shall be able to search for a book and open its details without instructions. The app follows Material Design 3. |
| NFR-02 | Performance | Search results should appear within 3 seconds on a normal connection (target). |
| NFR-03 | Performance | The app shall show a loading indicator right after an AI request, and a typical AI answer should arrive within 15 seconds (target). |
| NFR-04 | Reliability | The app shall not crash when there is no internet, an empty result, or an API failure; it shall show a clear error message. |
| NFR-05 | Security | Passwords shall never be stored or shown in plain text. Authentication shall be handled by a trusted service or library. |
| NFR-06 | Security | API keys shall not be stored in the public repository (kept in `local.properties`). |
| NFR-07 | Security | A Member shall not access Admin functions, and shall see only their own loans and profile. |
| NFR-08 | Privacy | The system shall collect only the data it needs (name, email, borrowing data) and use sample data for testing. |
| NFR-09 | Transparency | AI output shall always be marked as AI-generated and possibly inaccurate (see FR-28). |
| NFR-10 | Legal | Full book text shall be used only for public-domain books. |
| NFR-11 | Compatibility | The app shall run on Android phones with the minimum version defined in the Design phase. |
| NFR-12 | Maintainability | Code shall follow the Project Standards. The AI provider access shall be kept in one module so the provider can be changed. |
| NFR-13 | Availability | Features that depend on external services (AI, book data) may be unavailable when those services are down; the rest of the app shall still work. |
| NFR-14 | Testability | Every requirement shall have at least one test case (see RTM). |

## 4. Use Cases

### 4.1 Use Case List
| ID | Use case | Actor |
|---|---|---|
| UC-01 | Register and log in | Member, Admin |
| UC-02 | Search and view a book | Member |
| UC-03 | Borrow a book | Member |
| UC-04 | Reserve a book | Member |
| UC-05 | Get an AI book summary | Member |
| UC-06 | Get an AI recommendation | Member |
| UC-07 | Scan an ISBN | Member, Admin |
| UC-08 | Add or edit a book | Admin |
| UC-09 | Record a book return | Admin |

### 4.2 Main Use Cases

**UC-03 Borrow a book**
- Actor: Member. Precondition: Member is logged in.
- Main flow: (1) Member opens a book detail screen. (2) System shows that a copy is available. (3) Member taps Borrow. (4) System creates the loan, sets the due date, and reduces available copies. (5) System confirms and shows the due date.
- Alternate flow: No copy available → system offers Reserve (UC-04). Member has reached the borrow limit or has an overdue loan → system shows a message and does not borrow.
- Related: FR-11, FR-14, FR-18.

**UC-05 Get an AI book summary**
- Actor: Member. Precondition: Member is logged in and has internet.
- Main flow: (1) Member opens a book and taps Summarize. (2) Member chooses Whole book, Chapter, or Page range. (3) System gets the matching text. (4) System sends the request to the AI service and shows a loading state. (5) System shows the summary with the notice "AI-generated, may be inaccurate". (6) Member may ask follow-up questions in the chat.
- Alternate flow: Book has no full text → system gives a description-based summary and says so. AI service fails or limit reached → system shows an error message and lets the user retry later.
- Related: FR-24 to FR-30.

**UC-06 Get an AI recommendation**
- Actor: Member. Precondition: Member is logged in and has internet.
- Main flow: (1) Member opens the AI tab and chooses Recommend. (2) Member types a request or uses the default (based on favorite genres and history). (3) System sends the request to the AI service. (4) System shows recommended books with the accuracy notice. (5) Member opens a book detail from a recommendation.
- Alternate flow: AI returns a book not in the catalog → system hides it or marks it as not available in the library.
- Related: FR-21 to FR-23, FR-28, FR-30.

**UC-07 Scan an ISBN**
- Actor: Member or Admin. Precondition: Camera permission is granted.
- Main flow: (1) User opens Scan. (2) User points the camera at the barcode. (3) System reads the ISBN. (4) System shows the matching book.
- Alternate flow: Barcode cannot be read → system asks to try again or to type the ISBN. Book not in the catalog → system shows external book information (Admin may add it).
- Related: FR-19, FR-20, FR-35.

**UC-08 Add or edit a book**
- Actor: Admin. Precondition: Admin is logged in.
- Main flow: (1) Admin opens the book management screen. (2) Admin enters book data or fills it by ISBN lookup. (3) Admin saves. (4) System validates the data and updates the catalog.
- Alternate flow: Required field missing or ISBN already exists → system shows an error and does not save.
- Related: FR-31, FR-32, FR-35.
